# AI 의견의 검수 후보 생성

이 도구는 커밋된 공개 자료와 `prototype/public/data/scenarios.json`의 예제 좌표를 사용해 **새 후보 JSON 파일 하나**를 만듭니다. 후보는 자동 게시되지 않습니다. 생성 후 사람이 내용·자료 기준·현재 화면과의 일치를 검수하는 수동 준비 단계입니다. 기본 보고서는 이 도구나 AI 없이 사용할 수 있습니다.

2026-09-22 수정 검증은 합성 응답으로 수행했습니다. 실제 OpenRouter 생성 성공이나 제공자의 현재 가용성을 확인한 기록이 아닙니다. 수정 시점에 배포용 `prototype/public/data/precomputed_memos.json`과 `data-pack/out/precomputed_memos.json`은 모두 없었습니다.

## 실행 조건과 명령

Node.js 24와 저장소에 설치된 개발 의존성을 사용합니다. 외부 호출은 OpenRouter의 `/api/v1/chat/completions`에 직접 전송되며 운영 `/api/generate`를 거치지 않습니다. 실제 생성에는 이미 안전하게 설정된 `OPENROUTER_API_KEY`가 필요합니다. 키는 명령문·인수·소스·출력 JSON·공유 로그에 쓰지 않습니다. 셸 이력에 남는 키 대입 예시를 사용하지 마세요.

선택 변수 `OPENROUTER_MODEL`은 아래 네 값만 허용합니다. 생략하면 첫 번째 값입니다. 빈 문자열·임의 모델·유료 모델 식별자는 실행 전에 거절합니다. `LLM_MODEL`은 운영 서버 설정이고 이 도구는 읽지 않습니다.

- `google/gemma-4-31b-it:free`
- `nvidia/nemotron-3.5-lightning:free`
- `google/gemma-4-26b-a4b-it:free`
- `openrouter/free`

설정한 **단일 모델**을 요청합니다. 자동 재시도·대체 모델 전환·체크포인트는 없습니다. `model` 메타데이터는 요청한 설정값이며 `openrouter/free`가 선택한 실제 내부 모델을 증명하지 않습니다. 무료 식별자라도 가용성·사용 한도는 제공자 상태에 따라 달라집니다.

`prototype` 디렉터리에서 다음과 같이 실행합니다. 아래 경로는 예시이며, 실제로 이미 존재하는 검수 폴더 안의 **아직 없는 파일**을 지정합니다.

```sh
node node_modules/tsx/dist/cli.mjs scripts/precompute_memos.ts --help
node node_modules/tsx/dist/cli.mjs scripts/precompute_memos.ts --output /existing/review-folder/new-memos-candidate.json
```

`--help`는 사용법만 출력하고 종료코드 0, 인수가 없거나 형식이 틀리면 사용법만 출력하고 종료코드 2입니다. 두 경우 모두 환경변수·자료를 읽거나 외부 요청을 보내지 않습니다. 생성 성공은 0, 생성 실패·취소는 1입니다. 성공 메시지는 후보 저장만 뜻합니다.

## 생성과 거절 조건

요청 전에 키·모델·출력 경로·전체 fixture와 자료를 확인합니다. 빈 목록, 중복 id, 잘못된 좌표·용도지역·이름/id는 거절합니다. fixture의 `expectedGrade`와 `story`는 생성에 사용하지 않습니다. 현재 자료의 필수/선택 JSON과 CSV는 화면과 같은 구조 검증을 거칩니다. 선택 자료 부재는 `null`, 손상 자료는 고정 오류로 구분합니다. 데이터를 새로 수집하거나 수정하지 않습니다.

각 예제의 용도지역 출처를 계산 **전에** 입력에 넣습니다. `unknown`이면 초기 선택 상태의 `unknown`, 그 밖의 값은 수동 선택의 `manual`입니다. 사업·부지 조건은 현재 기본값이고 온라인 용도지역·규제·재해 조회는 모두 `null`입니다. `scoreSite()` → 체크리스트 → 프롬프트 → v4 전체 평가 서명을 같은 자료로 만듭니다.

프롬프트는 20,000자, 직렬화된 입력은 96KiB 이내여야 합니다. 요청부터 본문 수신까지 예제당 55초의 제한시간과 취소 신호를 적용하며 리다이렉트를 따르지 않습니다. Ctrl+C/SIGTERM은 진행 요청을 취소합니다. JSON 응답 전체는 1MiB, 원래 의견 본문은 UTF-8 128KiB 이내로 제한합니다. HTTP 성공만으로 저장하지 않고 다음을 모두 확인합니다.

1. JSON 콘텐츠 유형·응답 구조가 맞고 명시적 제공자 오류가 없음.
2. 선택 응답이 하나이고 `finish_reason`이 `stop`, 본문이 비어 있지 않은 문자열임.
3. `parseMemo`의 필수 구조가 완성되고 `ERROR`가 없음.
4. 현재 `buildMemoFacts`/`validateMemo`의 수치·표현·항목 검사에서 flag가 0임.
5. 모든 예제 검수가 끝났고 최종 후보 전체가 소비 코드의 2MiB 한도 이내임.

이 검사는 모든 자연어 의미나 원자료의 정확성을 보증하지 않습니다. 사람의 내용 검수가 필요합니다. 실패 로그는 `PRECOMPUTE_FAILED: 고정코드`만 출력하며 원시 키·모델값·제공자 응답·로컬 파싱 원문을 출력하지 않습니다. `UPSTREAM_TIMEOUT`, `UPSTREAM_UNAVAILABLE`, `UPSTREAM_INVALID`, `MEMO_INVALID` 등은 실패 경계이며 숨겨진 제공자 원인을 추정한 설명이 아닙니다.

## 출력 보존과 게시 검수

`--output`의 부모 폴더는 이미 존재하고 쓸 수 있어야 합니다. 기존 파일·디렉터리·심볼릭 링크와 두 배포 파일 경로는 거절합니다. 부모의 실제 경로와 대소문자 별칭을 대조하고, 저장 직전 다시 확인한 뒤 `wx`로 새 파일만 배타적으로 만듭니다. 원래 두 파일을 쓰거나 부모 폴더를 자동 생성하지 않습니다. 결과 JSON은 기본 파일 권한 0600으로 저장합니다.

생성 중 하나라도 실패하면 새 후보를 저장하지 않습니다. 저장 도중 오류가 발생하면 자신이 만든 불완전 후보만 정리합니다. 정리 자체도 실패하면 새 경로에 부분 파일이 남을 수 있으므로 **종료코드 1인 후보는 게시 대상이 아닙니다**. 프로세스 강제 종료·전원 차단에서도 같은 원칙을 적용하고 다른 새 이름으로 다시 생성합니다. 기존 파일을 자동 삭제·덮어쓰기하거나 복구 대상으로 삼지 않습니다.

게시 검수는 생성과 별도 작업입니다.

1. 종료코드 0의 후보를 열어 모든 예제의 원문·미확인 사항·근거·시점·금지된 확정 표현을 검토합니다. 자동 검증 결과만으로 실무 내용 검수를 대신하지 않습니다.
2. 대상 화면의 **현재 전체 입력·결과·체크리스트**와 `contextKey`가 같은지 확인합니다. 정확히 일치한 뒤에도 0.3km 거리 제한을 적용합니다. 온라인 조회 결과·조회시각·사업조건·자료가 달라지면 기존 후보를 사용하지 않는 것이 정상입니다. 좌표만 같다고 서명을 완화하지 않습니다.
3. 게시할 필요가 확인되면 기존 두 파일의 유무·내용을 보존하고, 검수된 동일 후보를 두 경로에 반영하는 별도 변경을 검토합니다. 생성 명령 자체에는 복사·동기화·배포 기능이 없습니다.
4. 두 파일의 동일 바이트·v4 서명·현재 UI fallback과 기본 보고서를 확인한 뒤 저장소의 PR·배포 절차를 따릅니다. 게시·배포·실제 fallback 확인은 각각 증거를 남깁니다.

이번 도구 수정과 합성 시험에서는 실제 후보 생성 호출, 원래 두 파일에 대한 복사, 게시·배포를 실행하지 않았습니다.
