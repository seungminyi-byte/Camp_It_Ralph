# 품질 확인 절차

계산·자료 처리·화면·온라인 연결을 각각 확인해 사용자가 같은 근거로 검토를 이어갈 수 있도록 합니다. 자동 검사와 실제 서비스 확인은 구분해 기록합니다.

## 자동 검사

[실행 안내](RUNNING.md)의 타입 검사, 린트, Vitest, 자료 검증, 프로덕션 빌드를 실행합니다. 인구의 결측과 0 처리도 다음 명령으로 확인합니다.

```bash
python3 -m unittest discover -s data-pack/scripts -p test_p03_population.py
```

브라우저 검사·접근성·성능·PDF 생성은 [통합 QA 안내](../prototype/e2e/README.md)를 따릅니다. 기대값은 [독립 계산 사례](../prototype/e2e/independent-cases.json)에 보관합니다. 고정 응답을 사용하는 검사는 외부 기관의 실제 응답 검증과 구분합니다.

## 주요 확인 항목

| 항목 | 확인할 결과 |
|---|---|
| 면적 | 연면적 30,000㎡·용적률 200%·건폐율 50%·4층이면 최소 대지 15,000㎡, 대지 10,000㎡이면 부족 5,000㎡ |
| 금융비용 | 평균 차입잔액 1,000억원·연 6%·12개월이면 60억원 |
| 결측과 0 | 차입잔액 미입력은 계산 보류, 명시적 0은 0원 |
| 비교 | 최대 네 후보, 조건 변경 후 재계산, 같은 완전한 비용 범위에서만 차액 표시 |
| 조회 상태 | 실패·부분·만료를 구분하고 이미 확인한 제약을 보존 |
| 입력 복구 | 소개 페이지 왕복·새로고침 후 허용된 입력 복원, 온라인 자료는 재조회 |
| 보고서 | 첫 장 요약·18항목·출처·추가 확인사항, 긴 문장과 표의 A4 쪽나눔 |
| AI | 18항목과 종합 의견·후속 조치·유의사항의 실제 생성, 입력 일치, 선택 부록 반영 |
| 접근성 | 키보드 탐색·초점 복귀·대화상자 이동·모바일 가로 넘침 |

## 실제 서비스 확인

1. [서비스](https://grand-site-dc.vercel.app)와 `/project`, `/team`, `/review`를 엽니다.
2. [가상 예제](EXAMPLE_INPUT.md)를 입력해 계산·비교·보고서를 확인합니다. 온라인 조회 시각과 자료 상태를 함께 기록합니다.
3. 선택형 AI 의견을 생성한 뒤 전체 형식·내용·현재 입력 일치를 확인하고, 보고서 부록에 포함해 봅니다.
4. 보고서를 PDF로 저장하고 모든 페이지의 한국어 글자·표·긴 문장·제목 쪽나눔을 확인합니다.
5. 배포 변경 시 Actions 성공, Vercel Ready와 해당 커밋·운영 별칭, 실제 정적 파일·API 응답을 대조합니다.

검증 기록에는 날짜·커밋·실행 조건·성공/미확인 범위를 남깁니다. 키·연락처·개인 경로·원본 세션 로그는 공개 기록에 포함하지 않습니다. HTTP 200만으로 AI 생성 완료나 기관자료의 완전성을 판단하지 않습니다.
