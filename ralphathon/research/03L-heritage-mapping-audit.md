## 1. 총괄에게 권하는 결정

**문화유산 레이어의 직접 적중과 번들의 천연기념물·명승 유형을 숫자 감점 없는 review로, 주변 거리 조회만의 적중을 reference로 구분한다.** review가 하나라도 있으면 인허가 참고점수와 종합점수 산정을 보류한다. reference만으로 감점·E 상한·산정 보류를 만들지 않는다. 다른 근거의 prohibited가 있으면 기존 40점 감점 1회·E 상한을 유지한다.

이는 허가가 쉽다는 판단이 아니다. 현재 입력과 응답에는 지정 고시, 해당 행위, 소유·지원 여부, 현행 경계와 행위기준이 없어 **허가절차가 있다는 사실에서 일률적 불허와 E등급을 도출할 수 없다는 근거 경계**다. 확인을 보류하면서 결과를 보존하는 제품 설계이며 법정 점수 기준이 아니다.

1. 등록문화유산 전체에 문화유산법 제35조를 적용하지 않는다.
2. 국가지정문화유산 제35조와 자연유산법 제17조도 허가 규정이라는 이유만으로 모든 사업을 금지 처리하지 않는다.
3. 500m는 현재 API의 검색 범위다. 법정 역사문화환경 보존지역으로 확정하거나 그 이름을 일괄 부여하지 않는다.
4. 직접 등록 + 주변 지정, 직접 지정 + 주변 다른 지정이 함께 있으면 둘 다 표시한다.
5. 성공한 API 조회와 법적 적용 확인은 다른 상태로 관리한다.
6. 다른 확인된 금지 제약은 review·reference·partial·실패로 지우지 않는다. 다른 분야 상수의 법적 정확성 전체는 이번 좁은 감사로 새로 보증하지 않는다.

### 4.2 직접·주변의 의미와 중복 처리

- 직접은 검색에 사용한 **좌표가 제공 도형에 적중**했다는 관찰이다. 선택 필지 전체, 사업부지 경계, 건축 예정 위치가 해당한다는 뜻이 아니다. 서버가 좌표를 소수점 4자리로 반올림하므로 원래 선택 좌표와 조회 좌표 차이도 경계 부근에서 중요하다.
- buffered는 그 좌표에 요청한 **검색 반경**으로 적중한 관찰이다. 법정 경계거리, 특정 유산까지의 정확한 거리, 법정 보존지역 포함을 확정하지 않는다. 500m 밖에는 제한이 없다는 부정 결론도 금지한다.
- **최소 수정:** LT_C_UO301의 direct-any-layer 억제를 없애고 직접·주변을 모두 유지한다. 중복 키에 source/layer/type/name/**relation**을 포함한다. 같은 이름의 직접 및 주변 기록도 identity가 없으면 모두 두어 “동일 대상 중복 포함 가능”이라고 설명할 수 있다.
- 현재 API는 mnum/ucode/feature id를 버리고 layer/buffered/name으로 먼저 합친다. 따라서 사라진 개별 대상은 클라이언트가 복원할 수 없다. 같은 용도명 둘을 서로 다른 실제 유산 2건으로 세지 않는다. 화면의 건수는 “조회된 유형·관찰” 범위다.
- **후속 정밀화 대안:** 서버와 parser에서 검증된 mnum 또는 feature id·ucode·uname 출처·고시 식별정보를 전달한 뒤 **동일 identity인 경우에만** 직접으로 주변 중복을 접는다. UOC510 샘플만으로 나머지 코드를 추정하지 않는다. 이는 최소 수정의 선행조건이 아니며 API 계약·테스트 범위를 늘리는 별도 변경이다.
- 현재 서버가 uname 부재 시 다른 “...구역/지역/공원” 속성으로 name을 대체하므로, name만 받은 분류는 **uname임을 보증하지 못한다**. 정확한 이름 분류도 잠정 표시이며 review를 해제하는 근거로 쓰지 않는다. 원문명 null/미상은 버리지 않는다.

## 5. 최소 수정 대안과 반론

| 대안 | 동작·수정량 | 반론과 판단 |
|---|---|---|
| **A. 유형별 review + 주변 reference + 직접 검토 미완료 시 점수 보류 (권고)** | 기존 2개 감점 수준과 분리한 2개 비점수 수준 추가. 상수·분류·집계·engine permitKnown·체크리스트/요약만 연결. 다른 금지는 유지 | 산정 보류가 늘고 기존 서울시청 E가 사라질 수 있음. 다만 E 대신 허가 판단 미확인을 명시하고 주요 확인사항에 남기므로 허위 안심을 막음. 실제 적합성 상승으로 설명하지 않음 |

| DATA/관련 주석 | 자료 범위·버전·계산 보류 정책 및 API 검색반경 설명 정정 | AGENTS 원본은 변경하지 않고 총괄 G005에서 이번 세부정책을 연결. API 주석의 “for 역사문화환경”·MapView 레이어 설명도 허용 범위에서 수정 |

필수 결과 분리:

    hasProhibited = hits 중 prohibited 존재
    requiresLegalReview = hits 중 review 존재
    scoringHits = hits 중 prohibited 또는 conditional
    permitKnown = 기존 필수 근거 조건 AND NOT requiresLegalReview
    capReason = hasProhibited이면 restriction, 없으면 기존 규칙
    composite.grade = hasProhibited이면 E, 그 외 점수 산정 가능할 때만 산정

실제 감점 근거에는 scoringHits를 쓰고, 전체 관찰 요약에는 모든 hit를 사용한다. 문화유산 review가 다른 금지와 함께 있다는 이유로 “문화유산 때문에 E”라고 설명하면 안 된다. 다른 conditional+review는 기존 conditional 감점 15점 1회가 내부 항목에 남되 인허가·종합 숫자점수는 보류한다.

조회 완전성은 기존 checked.vworld=ok/partial/none과 complete/failed로 유지한다. **법적 적용 미확인 때문에 API 조회를 실패로 위조하지 않는다.** restrictions evidence의 실체 확인은 별도 requiresLegalReview를 반영해 partial/caution으로 표시한다. 미산정을 0점이나 ‘제약 없음’으로 표시하지 않는다.

## 8. 조회 실패·보완 검색·검수 경계

- **CaseNote 미사용.** 이번 쟁점은 공개 현행 조문의 절차·분류와 코드가 그 경계를 넘는지 확인하는 감사다. 필요한 공식 본문을 확보했고 특정 사건의 판단·불허 기준·행정해석을 도출하지 않으므로 판례/유권해석 보완이 필수이지 않았다. 개별 입지의 허가 가능성 또는 조문 예외의 해석으로 확장되면 공식 기관 자료와 CaseNote를 보조 조사해야 한다.
- 본 실행의 get_law_text(mst=283307, jo=제17조)는 RESPONSE_PARSE_FAILED/HTML 안내·차단으로 실패했다. [실패 응답](../evidence/legal-audit/api-2.json)에 target=eflaw, JO=001700, response_invalid를 보존했다. 검색 0건·법령 부존재가 아니다. 인증값·설정을 조회하거나 안티봇 우회를 시도하지 않았다.
- 선행 총괄의 문화유산13/35·근현대17/18 조문 API 실패 4건은 legal-prep/HANDOFF.md의 **선행 기록**이다. 본 감사자의 재실행 성공으로 바꾸지 않았다.
- 웹 조회 도구에서는 자연유산 전체 LsiJoLinkP가 메뉴만 반환했고, H74/N17/N42의 구성된 lsSideInfoP URL은 internal error였다. 같은 공개 URL의 일반 HTTP GET에서는 법령명·시행일·해당 조문 본문을 정상 확인했다. 웹도구 실패와 공개 페이지 본문 확보를 구분한다. 전체본문 링크가 메뉴뿐인 결과를 법률 원문으로 인용하지 않았다.
