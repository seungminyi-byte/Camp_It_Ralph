## 2. 새 묶음의 구조와 구체적 매핑

[source-destination-plan.json](../../../overnight/N10/source-destination-plan.json)에 **36개 destination별 실제 source→destination** 매핑, 출처 SHA, 처리 방법, JSON 허용 필드와 제외 목록을 기록했다. 모든 현재 source는 존재한다. 미래 자료 **9개**는 별도 `generated_after_09` 항목이며 출처/상태가 미확정이다. 36+9는 계획 목적지 수이며 최종 ZIP 항목 수가 아니다. 새 파일을 복사·생성하지 않았다.

overnight-20260922/
  START_HERE.md

  실행안내.md / 예제입력.md / 검증요약.md / 야간변경내역.md

원래 최종 ZIP 안의 실행안내는 웹·clone·type/lint/test/build/E2E/PDF 절차만 안내하고 수동 사전 생성 명령은 싣지 않았다. 따라서 기존 ZIP에 잘못된 `--output` 예시가 들어 있었다고 쓰면 안 된다. **당시 `bb18284`를 재현하는 안내**이고 새 CLI 계약을 설명하지 않는 과거 문서다. 새 실행안내는 최종 병합 SHA를 고정해 선택형 CLI 절을 추가한다. 새 묶음은 소스 저장소 자체나 완전 오프라인 실행본이 아니며 저장소는 private인 접근 조건을 계속 명시한다.

CLI 절은 [현재 정식 안내](../../docs/PRECOMPUTED_MEMOS.md)와 다음 내용을 정확히 맞춘다.

- `prototype` cwd, Node.js 24, 설치된 개발 의존성. `node node_modules/tsx/dist/cli.mjs scripts/precompute_memos.ts --help`는 외부 호출 없는 도움말이다.
- 실제 생성은 이미 안전하게 설정된 키가 필요하고 OpenRouter로 직접 요청한다. 운영 `/api/generate`를 거치지 않는다. 사용자에게 키 원문을 요청하거나 예시 명령에 대입하지 않는다.
- `--output`은 **이미 존재하는 부모 안의 아직 없는 후보 파일**이어야 한다. `/existing/review-folder/new-memos-candidate.json`은 실행 전 대체해야 하는 문서용 예시임을 명시한다. 별도의 폴더 자동 생성·기존 파일 덮어쓰기·원래 두 배포 파일 갱신은 없다.
- CLI는 `OPENROUTER_MODEL`의 단일 무료 모델이며 서버 `LLM_MODEL`과 다르다. PR13의 서버 네 모델 목록은 실제 요청에서 실패했고 기본 세 모델로 복원할 예정이다. 최종 서버 목록은 복원 코드·문서·배포를 확인한 뒤 기입한다. CLI는 여전히 네 무료 모델 중 하나만 요청하며 두 경로를 같은 fallback 동작으로 설명하지 않는다.
- CLI 후보 저장 성공, 자동 내용 검사, 사람 검수, 현재 전체 v4 서명 일치, 두 배포 파일 게시, 배포와 실제 fallback 사용 확인은 각각 별도 상태다. 현재 실제 후보 생성·게시 완료 증거는 없다.
- 도움말 0 / 잘못된 인수 2 / 생성 실패·취소 1 / 후보 저장 0을 구분하고, 종료 1의 잔여 부분 후보는 게시하지 않는다. 합성 시험 통과를 실제 모델 성공으로 표시하지 않는다.

## 3. 공개 선별과 경로 처리

[링크 감사](../../../overnight/N10/link-audit.json)는 선택한 **16개 Markdown의 로컬 링크 발생 138건**을 확인했고 현재 workspace 안에서 모두 존재했다. 그중 **109건은 실행 저장소 밖으로 해석**된다. 이 수에는 원래 outputs의 내부 링크도 포함되므로 109개를 모두 결함으로 세지 않는다. 경고의 요점은 workspace에서 존재하는 링크가 휴대용 ZIP에 포함됐다는 뜻은 아니라는 것이다. 원격 링크는 새로 조회하지 않았으며 스캔 범위 밖 문서를 검수 완료로 세지 않는다.

- N 보고서의 `../../../overnight/Nxx/...`는 현재 work 폴더를 가리킨다. 보고서를 통째로 복사하지 않고 `evidence/README.md`로 요약해 포함한 정규 JSON에 상대 링크를 연결한다. 감사 스크립트·sandbox·심볼릭 링크·raw 로그를 따라 복사하지 않는다.
- N07 91행, N09 26행에는 실제 `/Users/...` 실행 경로가 있다. 최종 공개 요약에는 이 경로를 빼고 `source_id`, 저장소 상대경로, 출처 SHA와 시각으로 연결한다. N09/results의 sandbox 값도 허용 필드에서 제외했다.
- 새 docs/AI_DIAGNOSTICS.md의 소스 코드 링크는 패키지에 코드가 없으므로 최종 병합 SHA의 GitHub blob 링크로 바꾸고 private 접근 조건을 적는다. 코드 경로를 새 묶음 밖의 로컬 파일로 연결하지 않는다.
- 날짜를 유지한 발표 대본은 `../09-운영검증요약.md`와 `../operating-report-example/...`를 사용한다. 이를 포함하는 매핑을 만들었으며, 09 요약의 나머지 미포함 감사 링크는 `evidence/README.md`의 과거 검수 요약으로 연결한다. 발표 검수문 링크도 같은 방식으로 검사한다.
- 파일명은 destination와 ZIP entry를 NFC로 통일한다. 원래 발표 PDF는 디스크에서 NFD 이름이므로 원본을 rename하지 않고 새 사본의 이름만 NFC로 만든다. 복사 후 Markdown 링크도 동일 이름에 맞춘다. 같은 NFC 이름 충돌이면 포장 중단이다.
- 출처 내용의 해시 `source_sha256`와 경로·허용 필드를 조정한 사본의 `destination_sha256`는 다를 수 있다. 변형을 숨기지 말고 변환 종류와 두 해시를 적는다. 원본 presentation manifest는 바이트 불변의 원본 파일만 검증하는 과거 증거로 표시한다.
- 정규 JSON도 자동으로 공개 안전하다고 보지 않는다. 매핑의 허용 필드만 추출하고 중첩값의 실제 개인경로·예외본문·요청/응답/표식·provider raw값을 확인한다. 없는 필드는 null/미수집으로 남기고 성공 기본값을 넣지 않는다. 12필드 진단의 허용 분류·정수 code·시각·불리언과 trace 일치 여부만 필요하다.
- 원시 세션·계정/secret·자동화 설정·전체 환경·Vercel 원본 envelope·`.git`·`.env`·`.vercel`·node_modules·캐시·임시 파일은 제외한다. 기존 전달 ZIP과 submission ZIP을 새 공개 묶음에 기계적으로 중첩하지 않는다. root의 새 cutoff/redaction/검수를 거친 로그 제출본은 별도 인계 자료로만 참조한다.
- 비밀 패턴 검수는 허용 목록과 값 비반사를 함께 확인한다. 패턴 0건은 모든 비밀형식 부재 보장이 아니다. 무단 공개 전환·대회 제출·새 권한은 하지 않는다.

## 6. 09시 이후 확정할 필드와 최종 검사

[pending-final-fields.json](../../../overnight/N10/pending-final-fields.json)은 미래 완료값을 **null**로 뒀다. 마지막 기본기능 전체 확인 배포와 검수 후보, PR13 실패 실험, 계획된3모델 복원을 현재 최종 성공값과 분리한다.

1. **시간·범위 고정:** 09:00 이후 cutoff KST, 최종 코드/문서 SHA와 PR, 로컬 변경 목록, 현재 Goal 실제 반환을 기록한다. Goal이 없으면 새로 만들거나 허위 pause/complete를 호출하지 않는다. 10:00 이후 새 작업을 시작하지 않는다.

3. **실제 동작 수락:** 기본API 의미검사·익명 주요흐름·정적 바이트 대조를 대상 배포/시각과 연결한다. 이미 같은 바이트로 수락된 시험을 시간 채우기 위해 반복하지 않는다. AI 짧은 호출·18항목·현재 입력 일치·UI를 단계별로 적고, 실패·미수행은 그 상태로 남긴다.
