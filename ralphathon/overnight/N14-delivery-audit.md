# N14 — 전달 초안과 야간 로그 준비 독립 검수

검수 시각: 2026-09-22 01:30–01:35 KST. 후속 작업 최소 시각은 09:00, 하드 마감은 10:00이다. 현재 인계는 이 제한된 감사의 종료이며 야간 후속 전체 완료가 아니다.

**N12 전달 초안에서 구체적 결함을 발견하지 않았다. N13 로그 생성·감사에서는 수정할 결함 3군을 합성 자료로 재현했다.** 실제 원시 세션은 읽거나 내보내지 않았고 실제 유출·변조를 확인한 것은 아니다. N13의 실제 오전 내보내기 전에 아래 수정과 새 독립 검수가 필요하다.

## 확인한 결함

### F01 · P1 — 구조화된 비밀 필드가 마스킹과 감사에서 누락됨

대상은 `work/overnight/N13/build_submission.py` 46–51, 84–98, 103–116행과 `audit_submission.py` 30–39행이다. `Transformer.text()`가 문자열 안 JSON을 먼저 파싱하고 `walk()`가 각 값만 재귀 처리하므로 `api_key`나 `password`라는 키 문맥이 사라진다. 값 자체에 provider-token/Bearer 같은 패턴이 없으면 일반 비밀 후보가 그대로 남는다. 처음부터 객체인 경우에도 동일하다. `scan()`과 별도 `audit()`도 키에 연결된 값임을 검사하지 않는다.

고정 가짜 값만 넣은 두 반례, `{api_key: <TEST_ONLY 값>}`의 JSON 문자열과 `{password: <TEST_ONLY 값>}` 객체가 마스킹 0건·재검사 0건이었다. 이어서 실제 생성기 사본으로 합성 JSONL→ZIP→독립 감사 전 과정을 실행했고, 해당 값이 남은 채 `pass`, issue 0을 반환했다. 이는 단순한 알려지지 않은 토큰 형식 문제가 아니라 이미 정책에 열거한 credential assignment 문맥의 손실이다.

수정 범위는 생성기와 두 검사기의 구조화된 민감 키 문맥 처리다. 원본 키 이름·연결 ID와 값의 null/숫자/불리언·명시적 환경변수 참조 등 비밀이 아닌 설정은 구분하여 회귀를 정해야 한다. 실제 값은 위치·해시·바이트 길이 표지로 가리고 결과 보고에는 원문을 넣지 않는다.

### F02 · P2 — `agent_reasoning` 이벤트 형식이 내부 추론 제거 대상에서 빠짐

대상은 생성기 79–82, 104–108행과 감사기 16–20행이다. `reasoning`, `compaction`, analysis/reasoning 채널은 처리하지만 `event_msg.payload.type="agent_reasoning"`의 `text`는 일반 텍스트가 된다. 고정 합성 본문이 생성기→ZIP→감사 뒤에도 남았고 감사는 `pass`를 반환했다.

이 형식은 **이번 실제 로그에서 관측되었다고 말하지 않는다.** 총괄이 별도로 수행한 [이벤트 메타데이터 집계](../../../overnight/N13/event-schema-metadata-review.json)는 25세션 19,325행에서 이벤트 유형·키 형태만 확인했고 `agent_reasoning`은 0건이었다. N14는 이 집계 JSON만 읽었으며 원시 본문에 접근하지 않았다. 따라서 현재 실제 노출의 증거가 아닌, 지원할 내부 추론 이벤트 형식에 대한 예방적 검수 결함이다.

수정은 명시적 추론 이벤트 형식의 본문만 가리고 type·ID·행 연결을 유지하는 범위로 제한한다. domain 데이터의 일반 `summary`·`instructions` 필드를 모두 숨기는 식으로 확대하지 않는다.

### F03 · P2 — 독립 감사가 사본·행 연결에 선언된 해시 불일치를 놓침

대상은 `audit_submission.py` 48–66행이다. 원본 전체 해시, 행 수·주요 ID, ZIP과 현재 사본의 바이트 일치는 검사하지만 manifest의 `copy_sha256`·`copy_bytes` 및 `row-map.jsonl`의 사본 행 해시를 대조하지 않는다.

합성 내보내기 후 공개 문장 하나만 바꾸고 그 변경 사본을 ZIP에도 반영했다. manifest와 row-map은 원래대로 두었다. `copy_sha256`과 마지막 행의 `copy_line_sha256`은 둘 다 실제 바이트와 달라졌지만 감사는 `pass`, issue 0이었다. 실험 뒤에는 합성 사본과 ZIP을 원래 바이트로 복원했다. 실제 파일이 변조되었다는 뜻은 아니다.

수정은 manifest의 사본 크기·해시, 각 원본/사본 행의 해시·순서·세션 대응, 예상 ZIP 항목 집합을 독립 대조하는 것이다. 이 확인은 선택 패턴 검색이나 ID 검사만으로 대신하지 않는다.

## N12 전달 초안 검수

[첫 검수 결과](../../../overnight/N14/audit-results.json)의 A01–A06에서 다음을 확인했다. 후보·원본을 수정하지 않았다.

- exporter의 schema/project 코드를 재사용하지 않는 독립 selector 순회로 27개 투영 출처의 실제 값 469개를 비교했다. Python의 `False == 0`에 기대지 않고 타입까지 비교했다. 출처 해시·크기·source ID와 선택 필드가 대응했다.
- 결측 `aliasInspected` 1개는 null과 `missingFields`에 함께 남았다. 기존 실제 값 0·false·null과 결측을 혼동하지 않았다. 추가 합성 배열의 중첩 누락, 정수 0·실수 -0.0·false, 객체 전체 leaf와 잘못된 container의 거절을 확인했다.
- 모든 템플릿 출력은 동결 템플릿 바이트와, 직접 사본은 원본 바이트와 맞았다. 자기 소유의 새 폴더에서 고정 출처로 재생성한 52파일은 원래 후보와 완전히 같았다. 동결 출처 SHA를 자기 소유 spec 사본에서 틀리게 바꾸자 새 후보 폴더를 만들기 전에 중단했다.
- 현재 코드·789개 검사·실제 SSE 504 실패와 00:33의 이전 기본 운영 검수는 분리되어 있다. 15개 오전 확정 값과 전체 완료는 null/pending이며 대회 제출은 false다. 기존 9/21 Goal 완료값이 현재 완료값으로 승격되지 않았다.
- 재생성 시 후보 도구의 상대 경로·탈출·심볼릭 링크·선별 텍스트 검수도 통과했다. 이는 검수한 고정 후보의 휴대성과 재현성 범위이며 임의로 변경한 입력이나 모든 민감 문자열 형식에 대한 보증은 아니다. 실제 전달 ZIP은 만들지 않았다.

## 합성 로그 검수와 한계

첫 검수는 21검사 중 17통과·4실패이며, 실패 4개는 F01/F02의 생성·감사 두 지점이다. F03은 추가 E2E 반례로 별도 기록했다. **실패 수를 결함 수나 제품 회귀검사 수와 합산하지 않는다.** [마스킹 반례](../../../overnight/N14/redaction-counterexamples.json), [합성 E2E 결과](../../../overnight/N14/end-to-end-counterexamples.json)에 결과가 있다.

그 외 09시 이전 차단, 잘못된 label 차단, 이전 폴더 보존, complete row와 불완전 tail의 바이트 경계, 실제 행 해시 연결, model·effort·call ID와 사용자 합성 내용 유지, typed reasoning/system/developer/analysis 본문 제거를 확인했다. 사본 session ID 변조와 ZIP에만 추가한 항목은 감사가 거절했다.

실제 코드 사본의 `__file__` 기준 ROOT가 N14 내부 sandbox를 가리키도록 배치하고 시계만 메모리에서 09시 이후로 바꾸었다. 합성 세션 내보내기는 이 sandbox 안에서 2회 수행했다. 고정 가짜 본문만 사용했다. 실제 ROOT의 outputs나 기존 제출 ZIP, 원시 세션, 계정·설정·키에는 쓰거나 접근하지 않았다. 네트워크·설치·커밋·푸시·배포·하위 위임도 없다. 실제 로그 형식 전체의 지원 여부나 모든 비밀값 부재를 보장하지 않는다.

## 인계

N12/N13의 검수 시작 시 존재한 141개 입력 파일은 마지막에도 모두 같은 바이트인지 확인한다. 총괄이 동시에 추가한 이벤트 메타데이터 집계는 별도 읽기 전용 근거이며 기존 입력 변경으로 세지 않는다. 본 보고서와 자기 소유 증거는 [owned-manifest.json](../../../overnight/N14/owned-manifest.json)에 ROOT 상대 경로·크기·SHA-256으로 봉인한다. manifest 자신은 제외한다.

수정은 다음 실행자에게 넘긴다. N14는 대상 스크립트·후보를 수정하지 않았고 봉인 후 편집을 중지한다. 실제 모델 선택 검증은 총괄의 세션 메타데이터 기록을 따른다.
