## 총괄의 후속 작업

현재 후보는 그대로 보존하고 최종 자료는 **09:00 이후 검수 결과를 반영한 별도 `outputs/overnight-20260922/`**에 작성합니다. 이 재현 도구는 N12 내부 초안만 만들도록 제한했으므로 최종 outputs에 쓰도록 강제로 우회하지 않습니다.

오전에는 실제 최종 커밋·배포·관측시각과 필요한 영향 범위 검사를 확인하고, 모든 본문·표·코드 링크·선별 JSON을 같은 기준으로 갱신합니다. 발표에서 실제 AI 복구를 말할 조건이 충족되면 슬라이드·노트·대본을 함께 고치고 새 렌더 검수를 수행해야 합니다. 현재 원본 발표를 그대로 쓰면 보충문을 먼저 읽도록 안내합니다.

`최종후속검증.json`의 완료·검증·로그 cutoff·예약 종료·정리·ZIP 관련 값15개와 전체 완료는 null/pending입니다. 미래 운영 근거 5종·정리 근거1종도 같은 상태입니다. 완료보고 파일은 제목·본문에 DRAFT를 표시했습니다. 확인하지 못한 값을 성공으로 채우지 않습니다.

새 로그의 예정 상대 위치는 `session-logs/`입니다. root의 N13 export·검수와 실제 파일 생성 전에는 활성 링크를 만들지 않았습니다. 이전 세션 ZIP이나 원래 전달 ZIP을 중첩 복사하지 않았습니다. 실제 cutoff·세션 수·행수·해시와 인계 링크는 총괄이 최종 확인한 뒤 연결합니다.

최종 확정 후에만 새 manifest·ZIP을 만들고 빈 폴더 추출, 링크·CRC·바이트 해시, 기존87파일 보존, 실제 예약 종료 반환과 본인 프로세스 정리를 확인합니다. 대회 최종 제출은 별도 승인 경계를 유지합니다.

총괄 검수용 재실행은 N12 디렉터리에서 `python3 build_candidate.py verify --candidate candidate --report root-review.json`입니다. 새 재현은 `python3 build_candidate.py build --candidate candidate-root-rebuild --report root-rebuild.json`이며 결과 경로가 없어야 합니다. 저장된 입력 해시가 달라졌으면 중단하므로 이전 검사를 현재로 오인하지 않습니다. `prepare_candidate.py`는 이미 존재하는 템플릿 폴더를 덮어쓰지 않으며 무심코 다시 실행할 도구가 아닙니다.
