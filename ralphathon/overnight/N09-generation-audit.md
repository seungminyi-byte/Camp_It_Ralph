모든 쓰기는 N09 작업 폴더 아래 격리 fixture·새 합성 후보에만 수행했다. 실제 공개 번들은 읽기 전용으로 연결했으며 손상·경합용 파일은 격리된 사본에만 만들었다. 최종 후보 게시나 원래 두 출력 경로 생성은 없었다. 남겨 둔 `sandbox-*`의 파일은 **합성 시험물이며 게시용 AI 의견이 아니다**.

## 변경·회귀 경계

[보존 검수](../../../overnight/N09/preservation-check.json)는 20개 대조를 통과했다.

- 시작 시 고정한 11파일의 SHA-256이 시험 후에도 같다.
- 총괄의 00:54:48 배포 후보 8파일 manifest와 현재 바이트가 모두 같다. README/RUNNING 추가 편집이 시험 기준을 바꾸지 않았다.
- HEAD의 `generate.ts`에 모델목록 한 줄만 정확히 치환하면 현재 파일과 전체 바이트가 같다. 파서·무료 allowlist·55/15초·96KiB/20,000자/128KiB·진단 구현의 다른 변경은 없다.

두 API 테스트 diff도 읽었다. 기본값 세 형태의 정확한 순서, 명시한 세 모델의 단일 경로, 금지 모델의 요청 전 거절을 확인하며, 진단 기대 목록에 네 번째 모델이 반영되어 있다. CLI의 새 테스트는 관련 수명·파일·내용 경계를 포함한다. 총괄의 전체 49파일/790시험 및 N02-B 9파일/290시험·40응답 대조는 별도 선행 근거다. N09는 이를 자체 실행 수로 중복 계수하지 않았고 같은 전체 suite·UI·PDF·빌드를 반복하지 않았다.

`README.md`, `docs/RUNNING.md`, `docs/PRECOMPUTED_MEMOS.md`는 서버의 여러 모델 목록과 수동 도구의 단일 모델 설정, 새 후보 저장과 별도 게시, 실패·합성 검증 한계를 구분한다. 저장된 공식 routing 확인은 Chat Completions의 `models` 목록과 Anthropic Messages의 fallback 수 제한을 구분한다. N09는 해당 문서를 다시 인터넷 조회하지 않았으며 문서만으로 네 번째 모델이 실제 시도됐다고 단정하지 않는다.

## 실패 이력·잔여 한계

[run-history.json](../../../overnight/N09/run-history.json)에 실행 이력을 보존했다. 첫 실행은 12/12 통과·합성 25회였다. 이어 동일 계약의 타이머 발동·운영 취소 관찰을 보강해 최종 12/12 통과·합성 29회로 마쳤다. 기대값을 결과에 맞춰 바꾸거나 제품을 수정한 실패 이력은 없다. 탐색 중 추정한 ReviewApp·Vitest 설정 경로 두 개가 없어서 `rg`로 실제 경로를 찾은 도구 오류는 제품 시험 실패와 구분했다.

잔여 한계는 다음과 같다.

1. 현재 운영 AI의 typed504/timeout은 선행 N04 관측이다. 이번 변경의 실제 제공자 가용성·응답 성공·네 번째 모델 시도는 배포 후 별도 관측 사항이다. 유료 전환·추가 키·추가 호출로 우회하지 않았다.
2. 합성 정상 의견은 구조·자동 내용 검사·저장 경계를 확인할 뿐, 실제 AI 의견의 업무상 타당성이나 모든 자연어 의미를 검수하지 않는다. 자동 flag 0을 실제 내용 검수 완료로 확대하지 않는다.
3. 후보 쓰기는 기존 파일 덮어쓰기를 막는 작은 계약이다. cleanup 실패·강제 종료·전원 중단에서 새 경로에 부분 파일이 남을 수 있다는 문서 한계를 유지한다. 경합 반례에서 다른 위치로 이동된 부분 inode는 남았으며, 전세계 파일시스템 원자성이나 악의적인 파일시스템 교체 방어를 완성했다고 주장하지 않는다.
4. 사전 생성물은 원래 두 경로에 없고 이번에 게시하지 않았다. 별도 사람 검수·현재 전체 서명 확인·게시가 필요하다.

## 인계

제품 변경 요청은 없다. 총괄은 이 검수 기준 해시를 배포 후보와 최종 대조한 후 기존 승인 범위에서 PR·배포·실제 상태 관측을 진행할 수 있다. 원래 출력 두 파일은 종료 때도 부재이며, 실제 외부·계정 접근은 0이다. N09의 모든 프로세스는 종료했고 소유 파일 편집을 중지한다.

[owned-manifest.json](../../../overnight/N09/owned-manifest.json)에 이 문서와 N09 작업 파일의 바이트·SHA-256을 기록한다. manifest 자신의 해시는 제외하며, 격리 폴더의 symlink는 대상 문자열만 기록하고 원본 파일을 소유 파일로 포함하지 않는다. 다음 실행자의 제품 편집 전에 총괄이 소유권을 수락한다.
