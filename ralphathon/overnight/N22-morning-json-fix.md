## 변경과 검수

`accept_basic_checks.py`에 재귀 의미 비교를 넣었다. bool은 숫자와 구분하고 숫자1/1.0은 동등하게, dict 키 순서와 JSON 공백은 의미에 영향 없이 대조한다. 제품 파서의 본문은 저장된 원문을 다시 해석한 값이다. 원문을 읽지 못한 경우 null로 전달하고 원문 무결성 검사도 실패한다. 나머지 운영 코드와 제품 파서 브리지는 N20과 동일 바이트다.

[N21 감사](N21-morning-fix-audit.md)의 실행 전 고정18기대값은 바꾸지 않았다. 수락기16와 브라우저 시간 경계2를 N22에서 재생해 모두 기대와 일치했다. 이전 오수락 C02/C03/C04는 원문 대조와 제품 파서에서 거절한다. C05/C06 숫자표기·공백 양성 통제 및 정상false/null/0건/캐시/부분 상태는 유지한다. 총괄의 추가 고정 타입·중첩 비교10개도 통과했다.

수정자인 총괄이 독립 감사의 기존 고정 사례를 재생한 결과다. N22 이후 별도 독립 감사로 표시하지 않는다. 제품789검사·N20의39/4/6은 변경이 없어 반복하지 않았고 검사 수에 더하지 않는다. 로컬 파서20프로세스, HTTP8·별칭2·브라우저라우트4 모의 시도만 있었다. 실제 외부명령·네트워크·브라우저 실행·AI추론0이다.
