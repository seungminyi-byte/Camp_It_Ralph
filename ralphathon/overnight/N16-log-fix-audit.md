# N16 — N15 로그 수정본 독립 반례 감사

2026-09-22 01:46–01:51 KST. 최소 계속 시각은 09:00, 하드 마감은 10:00이다. 이 문서는 제한된 감사 결과이며 야간 후속 전체 완료가 아니다. 총괄이 지정한 Astra/xhigh로 범위를 인계받았으며 실제 모델 메타데이터 확인은 총괄 기록을 따른다. 하위 위임과 전역 설정 변경은 없다.

**실제 내보내기 전 수정이 필요한 결함 1군을 확인했다.** N15가 고친 구조화 민감 값 처리에서 두 예외 분기가 상위 민감 문맥을 전달하지 않는다. 새 독립 검사 44개 중 40개 통과·4개 실패이며, 4개 실패는 같은 두 분기의 단위 검사와 전체 내보내기 재현이다. 4개 독립 결함이나 실제 유출로 계산하지 않는다.

## F01 · P2 — 예외 재귀 분기에서 민감 문맥 소실

대상은 [생성기](../../../overnight/N15/build_submission.py)의 **94행과 105행**이다.

| 분기 | 합성 입력 형식 | 실제 처리 | 영향 |
|---|---|---|---|
| 105행, type 없는 객체의 일반 message | `password: {message: "합성값", entry: false}` | entry는 가리지만 message 재귀에 sensitive를 전달하지 않음 | message 값이 남아 최종 재검사에서 실패 |
| 94행, 추론 객체의 KEEP 메타데이터 | `cookie: {type: "agent_reasoning", id: "합성값", text: false}` | text는 가리지만 KEEP 재귀에 sensitive를 전달하지 않음 | 민감 문맥 안 type/id가 남아 최종 재검사에서 실패 |

실제 반례는 한글·이모지·결합문자·NUL을 포함한 **고정 합성 값**을 사용했다. 환경변수 값이나 실제 자격값은 읽지 않았다. [결과](../../../overnight/N16/results.json)의 U06/U07이 처리 결과·변환표·생성기 재검사·독립 감사 결과를 남긴다.

X01 두 사례는 별도 합성 JSONL에서 생성기의 `main()`까지 실행했다. 모두 `RuntimeError`로 중단했고 ZIP은 생성되지 않았으며 기존 latest는 정상 3세션 묶음을 계속 가리켰다. 따라서 외부 제출본이 성공적으로 생성되거나 유출됐다고 판단하지 않는다. 다만 재검사 전에 쓰인 **새 label 폴더의 부분 JSONL에는 합성 미가림 값이 남았다.** 실패 폴더를 제출 자료로 선별하면 안 된다. [부분 사본 관측](../../../overnight/N16/failed-candidate-observation.json)은 sandbox 파일의 존재·해시와 합성 값 잔존 여부만 기록한다.

최소 수정 범위는 두 예외 재귀 호출의 상위 `sensitive` 전달이다. 추론 객체의 일반 로그 ID는 민감 문맥이 아닐 때 계속 보존해야 한다. 민감 키 아래 객체와 실제 로그 메타데이터의 처리 우선순위를 명확히 하고, 원래 null·빈 문자열·정확한 환경참조·전체 유효 WITHHELD 표지 예외 및 일반 공개 본문·숫자·불리언 보존을 재확인한다. 이 감사에서는 코드를 수정하지 않았다.

## 통과한 독립 검사

[고정 기대값](../../../overnight/N16/expectations.json)을 실행 전에 작성하고, N15의 89개 하니스를 재사용하지 않은 [자체 감사 코드](../../../overnight/N16/audit.py)를 작성했다.

- 민감 키 아래 중첩 배열의 정수·음수 영점·false·UTF-8 문자열을 원래 값 길이와 SHA-256으로 가림. 다중 직렬화 JSON과 여러 패턴이 겹치는 본문에서도 이미 만든 표지의 해시를 원문 해시로 다시 기록하지 않음.
- 정확한 환경변수 참조와 전체 유효 WITHHELD 표지는 계약상 예외로 보존. 접미 값이 붙은 참조/표지와 잘못된 표지는 가림. 일반 domain의 0·false·null·summary·instructions는 보존.
- 현재 Reasoning·analysis 채널 및 agent_reasoning의 본문을 가리고 연결 ID를 보존. 수정 전 비가림 합성 값을 생성기 재검사와 독립 내용 감사가 각각 거절.
- 3개 합성 세션·21행을 생성기 → ZIP → 독립 감사로 검증. 서로 다른 행의 LF/CRLF를 정확한 바이트로 대조하고, 불완전 tail 및 유효 JSON이지만 마지막 LF가 없는 tail을 제외 길이와 함께 보존.
- 사본과 ZIP만 함께 변경한 경우, 같은 길이 ID 변경, 원본 CRLF 변경, row-map 중복·누락·세션 순서·ordinal 변경을 거절. 사본/행 해시를 갱신해도 주요 call ID·item ID·turn model·timestamp 차이와 민감 값·agent_reasoning 본문은 거절.
- ZIP 중복·누락·상대경로 이탈·절대경로·추가 디렉터리 항목 및 목적지 심볼릭 링크를 거절. 원본 완전행 경계와 tail 길이 선언 변경도 거절.

이후 [감사기의 실제 main 진입점](../../../overnight/N16/cli-check.py)을 별도로 실행해 정상 exit 0, row-map 중복 변조 exit 1, 복원 exit 0을 확인했다. [진입점 결과](../../../overnight/N16/cli-results.json)는 위 44개와 겹치는 3개 추가 호출이며 새 결함 수나 제품 회귀 수에 합산하지 않는다. 감사기는 생성기를 import하지 않으며 직접 원본·사본·row-map·ZIP을 읽는다. 두 도구가 서로의 pass 선언만 감싸는 형태는 아니다.

## I01 · 정보성 보장 경계 — 변환표의 원문 해시 의미

감사기는 `transformations.json`의 ZIP·로컬 바이트 일치는 확인하지만 개별 event의 sha256을 원래 값과 독립 대조하지 않는다. [추가 탐색](../../../overnight/N16/transformation-provenance-boundary.json)에서 변환 event 하나의 sha256만 64개의 0으로 바꾸고 해당 ZIP 멤버를 맞췄을 때 감사는 pass했다. 원본·사본·manifest·row-map은 그대로였다.

N15의 명시적인 F03 수정 계약은 **사본 및 row-map 선언 해시·대응 검사**이므로 이 관측을 새 F03 미충족으로 계산하지 않았다. 생성된 변환표의 원래 UTF-8 값 해시는 독립 합성 검사에서 맞았다. 다만 인계 설명에서 “감사가 변환표의 모든 원문 해시 의미까지 검증한다”고 확대해서는 안 된다. 모든 선언과 파일을 함께 교체한 공격의 인증 보장도 없다.

## 보존·재현·수락 경계

- [N15 원본 manifest 검사](../../../overnight/N16/N15-manifest-verification.json)의 161개 소유 파일 크기·SHA-256이 모두 일치했다. 원래 생성기·감사기의 시작/종료 해시도 일치한다.
- N15 두 스크립트를 N16 sandbox로 복사하고 ROOT가 sandbox인지 확인했다. 생성기 시계만 메모리에서 09시 이후로 바꿨다. 09시 전 실행 차단도 별도로 확인했다.
- 합성 export 완료 1회, 09시 이후 합성 export 시도 총 3회다. 원시 세션 읽기·실제 제출 사본 읽기·실제 export·실제 outputs 쓰기·네트워크 요청은 0이다.
- 제품, N15/N13/기존 도구, N12, 원본 outputs, 상태 문서, 계정·설정·키는 수정하지 않았다. 설치·커밋·푸시·배포도 하지 않았다.
- [findings.json](../../../overnight/N16/findings.json)에 결함군·정확한 행·최소 수정 범위와 한계를 기록했다. 모든 비밀 유형·사내 사실·미래 스키마 부재를 보장하지 않는다.

현재 권장은 F01 수정 후 새로운 독립 검수와 총괄 수락까지 실제 export 보류를 유지하는 것이다. 소유 파일은 [owned-manifest.json](../../../overnight/N16/owned-manifest.json)에 ROOT 상대 경로·바이트·SHA-256으로 봉인한다. 봉인 뒤 편집을 중지한다.
