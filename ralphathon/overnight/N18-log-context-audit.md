# N18 — N17 민감 문맥 수정의 독립 교차 감사

2026-09-22 01:56–02:01 KST. 오전 09:00까지 후속 작업과 10:00 하드 마감을 유지한다. N18은 제한된 감사 산출물이며 야간 후속 전체 완료가 아니다. 시작 시 ROOT와 저장소의 AGENTS.md 및 N16/N17 보고서·G039·N17 두 도구를 읽고 적용했다.

**새 고정 교차 사례 12개를 포함한 26개 검사가 모두 통과했다. 새 결함은 발견하지 않았다.** N17의 두 수정 경로를 실제 생성기에서 통과시킨 합성 2세션·16완전행·ZIP 1개를 만들고, 독립 감사기의 실제 `main()`도 통과했다. 일반 공개 ID·행 순서·정확한 예외는 유지됐으며 민감 문맥 안의 message·role/type/channel·연결 메타데이터는 고정 기대값대로 가려졌다.

이번 검사는 N15의 89개·11개, N16의 44개 하니스를 재실행한 결과가 아니다. [기대값 작성기](../../../overnight/N18/fix_expectations.py)에서 전체 예상 구조와 UTF-8 원문 해시를 직접 작성하고 N17 모듈을 불러오기 전에 [고정 기대값](../../../overnight/N18/expectations.json)을 저장했다. 기대값 SHA-256은 `9a715fea321b9266b7444705fba34ecb4d21a138f6a1885498a3a9431df81089`이며 실행 뒤에도 같다. [자체 감사 코드](../../../overnight/N18/audit_crosscases.py)와 [전체 결과](../../../overnight/N18/results.json)를 보존했다.

| 교차 범위 | 고정 사례 | 확인한 결과 |
|---|---|---|
| 상위 민감 문맥의 다단계 message | C01, C02, C05, C12 | 배열·객체·빈 type·중첩 hidden KEEP 분기를 지나도 민감 문맥 유지, 형제 공개 객체에는 전파되지 않음 |
| system/developer/analysis/reasoning 메타데이터 | C02–C06, C10 | 민감 문맥의 role/type/channel/id/시각/0/false 가림, 일반 추론·지침 객체의 공개 연결 ID 유지 |
| 정확한 예외와 유사 문자열 | C03, C07, C08 | null·빈 문자열·정확한 환경참조 5종·전체 유효 WITHHELD 보존, 공백·개행·접미사·불완전 표지는 가림 |
| 문자열 JSON과 혼합 문맥 | C09–C11 | 3겹 직렬화 내부의 두 수정 경로 처리, 민감 키 아래 직렬화 문자열은 전체 가림, 공개 KEEP 컨테이너 안 민감 키만 가림 |

각 교차 사례는 예상 전체 값, 입력 불변, 변환 event의 종류·UTF-8 길이·원문 해시·사유, 생성기 재검사 및 독립 내용 감사 결과를 한 검사로 묶었다. 같은 12개를 합성 JSONL의 실제 도구 출력 행에 넣어 export 후에도 전체 값이 같음을 확인했다. 단위 확인과 전체 실행의 동일 입력을 서로 다른 24개 독립 사례로 계산하지 않는다.

## 실제 진입점과 묶음 확인

- N17 두 스크립트를 N18 sandbox에 **바이트 그대로 복사**했다. ROOT가 sandbox인지 확인했고, 독립 감사기는 생성기를 import하지 않는다. N17 파일 자체나 전역 시계는 변경하지 않았다.
- 실제 현재 시각의 생성기 CLI는 exit 2로 차단되며 출력 폴더를 만들지 않았다. 메모리 시계 08:59:59도 차단됐고 정확히 09:00:00에서는 합성 export가 완료됐다. 실제 도구의 09시 가드는 유지됐다.
- 완전한 합성 2세션·16행과 6개 ZIP 항목을 확인했다. LF/CRLF를 포함한 원본 바이트, 원본/사본 행 해시, 세션·ordinal·timestamp·공개 call ID 및 순서를 고정 기대값과 대조했다. ZIP의 정확한 항목 집합·CRC·모든 항목 바이트도 직접 대조했다.
- [정상 감사 main](../../../overnight/N18/clean-main.json)은 exit 0·0 findings·16행 비교다. 아래 네 변조는 사본/manifest/row-map의 관련 해시와 ZIP까지 맞춘 뒤 실제 감사 main을 호출했다. 행 순서 검사는 row-map과 ZIP만 바꿨다.

| 변조 | exit | 거절 근거 |
|---|---:|---|
| 민감 KEEP `id`에 합성 원문 복원 | 1 | `structured_credential_value` |
| 다단계 typeless message에 합성 원문 복원 | 1 | `structured_credential_value` |
| 공개 payload call ID 변경 | 1 | `payload_identity_mismatch` |
| 세션 경계 row-map 순서 교환 | 1 | `row_map_mismatch` |

이후 원래 JSONL·manifest·row-map·ZIP을 정확한 바이트로 복원하고 [복원 main](../../../overnight/N18/restored-main.json)의 exit 0·0 findings를 확인했다. 실제 독립 main 호출은 정상 1회·변조 4회·복원 1회, 총 6회다. 합성 export 생성은 1회다. 감사 호출 수와 생성 횟수를 구분한다. ZIP SHA-256은 `cad00c85e02e35e7bdb8a91845d776e310b2103591346ecb933850f30d809270`이다.

## 보존·보장 경계

[실행 전](../../../overnight/N18/N17-preservation-before.json)과 [실행 후](../../../overnight/N18/N17-preservation-after.json)에 N17 manifest SHA-256 `aa13bc64218940cab2b95b6dbe66f861fb86e7bbf420153d9ba34fcd95959d37`과 소유 120파일의 길이·SHA-256이 모두 일치했다. 합성 원본·기존 출력 역할의 sentinel·N17 도구 복사본·고정 기대값도 보존했다. 실행 후 감사 코드에서 평가되지 않는 `if False` 분기만 제거했으며 동일한 실제 읽기 식은 유지했다. 최종 코드는 AST 구문 검사했다. N17 도구에는 이 정리도 적용하지 않았다.

N16 I01은 정보성 한계로 유지한다. 생성된 60개 합성 변환 event의 값 해시는 고정 기대값과 맞았으나, 독립 감사기가 모든 event 해시의 원문 의미를 인증하는 것은 아니다. 모든 선언과 파일을 함께 교체한 공격의 인증이나 모든 비밀 유형·미래 스키마의 부재도 보장하지 않는다. 해당 한계를 새 수리 범위로 확대하지 않았다.

합성 파일은 N18 sandbox 안에만 있다. 생성기의 POLICY 문구는 원래 실제 export용 템플릿이므로 sandbox 안 문구를 실제 세션 생성 근거로 해석하지 않는다. 실제 세션·실제 제출 사본 읽기, 실제 export, ROOT의 실제 outputs 쓰기, 네트워크·설치·Git·제품·설정·상태 문서 변경은 0이다. N16/N17과 기존 결과물은 수정하지 않았다.

도구 설명상 Astra는 복합 추론, Sol/Terra는 일반 에이전트·코딩, Luna는 속도·비용, 5.5는 이전 세대 일반 작업에 적합하다. 이번 제한된 보안 감사에서는 정확성과 독립 기대값 설계가 우선이므로 상속된 실행 모델을 유지했고 전환·추가 위임은 하지 않았다. 실제 모델 메타데이터는 총괄의 확인 기록을 따르며 이 감사에서 원시 세션을 열어 확인하지 않았다.

수락 권고: N17 두 분기 수정은 이 독립 감사 범위에서 수락 가능하다. 실제 오전 export는 총괄 수락과 09시 가드 및 원래 절차에 따른다. 제품의 789개 회귀와 이 도구의 26개 검사를 합산하지 않는다. [소유 manifest](../../../overnight/N18/owned-manifest.json)에 ROOT 상대 경로·크기·SHA-256으로 봉인하고 편집을 중지한다.
