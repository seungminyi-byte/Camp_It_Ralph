## 1. 결과 화면과 비교

결과의 중심을 확인한 주요 제약 → 중요한 미확인 → 다음 확인사항 → 선택 입력 → 근거 → 접힌 참고점수로 배치했다. `reviewGroups`는 기존 엔진 이슈를 표시 묶음으로 나누며 새 점수나 위험 우선순위를 계산하지 않는다. 각 묶음과 다음 행동은 엔진 순서를 유지한다. 첫장 행동은 앞 3개를 요약하고 나머지 개수와 전문 위치를 안내한다. 마지막 설계·인입 경로 2개를 최우선으로 올리지 않는다.

비교는 실제 `CompareEntry[]`와 `compareSummary`를 그대로 사용한다. 0핀은 비교 후보 없음, 1핀은 2곳 이상에서 비교 가능, 2~4핀은 실제 저장 순서의 표를 제공한다. 현재 후보가 담은 목록에 포함되는지는 불투명 pin ID로 구별한다. 현재 E가 핀 A~D에 자동 추가되지 않는다. 비용 방식·범위·입력이 완전할 때만 최대−최소 차액을 표시한다. 미입력은 0으로 바꾸지 않는다.

모바일에는 후보 카드, 전체 항목에는 가로 이동 가능한 포커스 영역을 추가했다. 비교 닫기·Escape는 연 버튼으로 포커스를 돌린다. 온라인 상태·미산정·국가유산 적용 확인 필요·E등급 상한은 기존 엔진과 법적 계약을 유지했다.

## 2. 열린 보고서의 수명

`MemoPanel`의 ‘보고서 열기’에서 현재 입력으로 `scoreSite`와 `buildChecklist`, 실제 핀들의 `scoreSite`를 동기 재평가한 뒤 `captureReport`로 소비 자료만 깊이 복사·동결한다. 전국 원자료는 복제하지 않고 constants, 입력, 결과, 체크리스트, 핀, 출처, 조회 정보, 당시 적격 AI만 저장한다. 엔진에는 평가 기준시각 인자가 없으므로 각 호출 간 수 ms 차이까지 동일한 시각이라고 주장하지 않는다. 하나의 동기 capture에서 입력과 응답이 섞이지 않는 계약이다.

보고서 기준시각 `capturedAt`, 자료 기준일, API `fetchedAt`은 별개로 표시한다. 조회 상태는 렌더 시점의 현재 시각이 아니라 캡처 시각으로 판단하므로 열린 보고서/PDF가 나중에 바뀌지 않는다. 이전 관찰·부분 조회·실패는 해당 없음으로 바꾸지 않는다.

화면과 `#print-root`는 같은 snapshot ID를 사용한다. 입력·근거·조회 revision·담은 후보·현재 후보가 바뀌면 ‘열기 이후 변경됨’ 안내가 나오고, 다시 열 때만 갱신한다. PDF 파일명도 snapshot의 후보와 캡처 날짜로 고정한다. 인쇄는 DOM 반영 및 폰트 준비 후 시작하고 인쇄 종료 시 제목·포커스를 복원한다. 닫기와 경로 이탈은 print-root를 제거한다.

후보별 `key` 재생성과 지원외 후보에서의 조건부 unmount를 제거했다. A 보고서를 열고 B를 고르면 A 보고서를 유지하며 재개방 시 B가 된다. 지원외 C에서는 이전 보고서를 유지·출력할 수 있으나 C의 새 보고서와 AI 생성은 막는다. 검토 내용 지우기나 검토 경로 이탈 시에는 제거된다. AI의 기존 context/revision/abort 검사는 유지한다.

AI는 기본 미포함이다. 현재 입력·근거와 일치하고 04B 검사에 적격한 완료 응답을 사용자가 명시 선택한 뒤 새로 연 보고서에만 별도 부록으로 담는다. 이후 live AI가 해제되어도 이미 연 보고서의 당시 적격 부록은 고정된다. 다시 연 보고서에는 오래된 부록이 들어가지 않는다. 외부 AI를 실제 호출하지 않았고 고정 합성 응답만 사용했다.

## 3. 비교 자료 만료 보완

총괄이 재현한 비선택 핀의 10분 만료 후 점수 잔존을 수정했다. `useEvidenceClock`은 전체 현재·핀 조회 중 가장 가까운 미래 만료 타이머 1개를 두고 focus/visibility 복귀에도 재계산 revision을 올린다. 비교 열기와 보고서 열기에서도 재평가한다. 이미 지난 시각을 타이머 후보에서 빼 0ms 무한 반복을 막고 타이머·이벤트를 정리한다. 새 자동 네트워크 반복 조회는 추가하지 않았다. 과거 적중 원문 보존과 오래된 미해당 판정 폐기는 엔진 계약 그대로다.

## 4. 실제 A4 출력
