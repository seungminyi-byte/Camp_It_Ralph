## 제작 방식과 범위

presentations, pdf, computer-use 스킬을 읽고 적용했다. `load_workspace_dependencies`로 확인한 번들 26.909.12148의 Node 24.19.0 / Python 3.12 런타임과 `@oai/artifact-tool` JavaScript ESM을 사용했다. 폰트는 설치된 Nanum Gothic(나눔고딕)이며, 슬라이드는 1280×720 CSS px다. PPTX는 5슬라이드·5발표자 노트이고 모든 제목·본문·숫자·각주는 편집 가능한 텍스트다. 사진·실제 UI·보고서 첫 장은 개별 이미지 객체다. 전체 슬라이드를 이미지로 만들지 않았다.

공식 최종화 도구의 PPTX 구조, 5쪽 수, 글자·도형 배치, 폰트 정책, Artifact Tool 재가져오기가 모두 통과했다. 최초 v1은 재가져오기 자식 프로세스에 `RUNTIME_NODE_MODULES`가 없어 실패했으며, 문서에 지정된 번들 경로를 설정한 후 v2와 최종본을 통과시켰다. 이 실패를 제품 결함이나 최종 파일 검수 성공으로 섞지 않았다.

원본 사진을 수정하지 않았다. 기존 검수 WebP를 PPTX에 삽입하고 PowerPoint의 비율을 유지하는 중앙 크롭만 적용했다. 도구의 실제 내보내기 `srcRect`는 2쪽 위/아래 각 1.627%, 3쪽 위/아래 각 23.5%다. 팀원 얼굴과 전신, 운영 화면의 핵심 제약·미확인 표시를 보존한 것을 실제 렌더로 확인했다. 코드의 crop 인수와 별개로 실제 내보내기 결과를 검사 기준으로 삼았다.

최종 PPTX를 **Microsoft PowerPoint에서 실제 열어** 복구 경고 없이 5개 슬라이드와 노트를 확인했다. 1~5쪽을 각각 선택해 한글·사진·배치를 직접 읽었다. 5쪽 제목을 선택했을 때 텍스트 객체 선택 테두리와 나눔고딕/36.8pt 편집 컨트롤이 나왔다. 편집 내용을 저장하거나 타인의 파일을 바꾸지 않았다.

그 파일에서 ‘인쇄에 적합’을 선택해 로컬 네이티브 PDF를 내보냈다. Microsoft 온라인 서비스 전자배포 옵션은 사용하지 않았다. 저장된 PDF의 5쪽을 Poppler로 새로 렌더하고 **다섯 페이지를 모두 직접 확인**했다. 네이티브 PDF와 PowerPoint 화면에서 자름·겹침·한글 깨짐이 보이지 않았다. 링크 색은 PowerPoint의 하이퍼링크 테마색을 따르며 문자열과 목적지는 같다.

PPTX XML의 모든 편집 텍스트를 PDF 추출 텍스트와 페이지별로 대조했다. Unicode NFKC 후 공백과 NUL을 제거한 비교에서 누락 객체 0개다. PPTX의 노트 발화문도 대본 원천 JSON과 모두 일치했다. 면적·금융 11개 표시 문자열과 3개 독립 산식을 대조했다. 본문에 확인되지 않은 절감률·공급 확정·인허가 확정을 넣지 않았다.

PDF 읽기 경계: 네이티브 Quartz PDF를 pypdf로 읽을 때 xref 항목의 `wrong pointing object ... offset 0` 경고 20개와 텍스트 사이 NUL을 관찰했다. 원본 내보내기 PDF를 임의 재작성하지 않았다. pdfinfo는 5쪽을 읽었고, Poppler가 5쪽을 모두 렌더했으며, pypdf도 전쪽 본문을 추출했다. 경고 원문과 정규화 방법을 증거에 남겼다. 이는 PowerPoint 복구 경고와 구분한다.
