## 4. 실제 결과 예시의 재현 조건

새 UI 산식이나 별도 홍보 숫자를 만들지 않았다. `work/07-design/server.mjs`의 로컬 합성 검증 서버로 제품 `dist`를 제공하고, `work/07-design/make-example.mjs`에서 실제 `ResultOverview`를 캡처했다. 프로덕션에 mock 토글·합성 API 경로를 넣지 않았다.

- 합성 조건: 계획 연면적 30,000㎡, 확보 대지 10,000㎡, 용적률 200%, 건폐율 50%, 지상 4층. 엔진의 최소 대지 15,000㎡에 대해 결과 화면에 **5,000㎡ 부족**이 표시된다.
- 고정 온라인 응답: 용도지역 industrial hit/complete, 규제·재해 no-hit/complete. 이는 해당 위치의 실제 법적·물리적 상태에 관한 검증이 아니다. fetchedAt은 생성 시각이며 원자료의 기준일이 아니다.

## 5. 검토 앱의 읽기·조작 흐름

총괄 채택 G011에 따라 1023px 이하에서는 결과/지도 전환을 사용한다. 검색, 현재 선택, 담은 후보, 보고서·PDF와 상세조건 바로가기는 전환 밖에 있다. 처음 사용자에게 주소 검색과 지도 선택 동선을 모두 제공한다. 1440px에서는 기존 지도/결과 2열과 패널 폭 조절을 유지한다.

지도와 MemoPanel을 전환마다 재생성하지 않는다. 숨긴 pane은 `display:none`으로 키보드·접근성 트리에서도 제외된다. 지도 재표시 때 기존 ResizeObserver/Leaflet invalidateSize가 복원한다. 지도에서 후보를 고르면 결과로 전환하고 읽을 결과 h2로 포커스를 옮긴다. 지도 우회 링크는 기본 1px/clip-path 상태, 포커스 때만 표시된다. 기존 `top:-200px` 방식에서 상대 좌표 때문에 테두리가 노출되던 결함을 총괄 발견 후 고쳤고 독립 재검수했다.

미확인은 엔진 순서의 처음 3개 제목을 보여주고 **전체 N개와 상세 근거**를 native details에 모두 보존했다. 제약·미확인·다음 질문 → 선택 입력 → 근거 → 접힌 참고점수 순서는 유지한다. 상세조건과 보고서 도구는 상단에서 바로 접근하며 이미 열린 보고서를 새로 만들지 않는다.

비교는 1023px 이하에서 기존 후보 요약 카드를 먼저 보여주고 상세 표를 그 아래 보존한다. 601–1023px는 2열 카드, 600px 이하는 1열이다. 1440px는 넓은 대화상자에서 네 후보 열을 함께 읽는다. 상세 표는 키보드 포커스와 가로 이동 안내가 있는 영역이다. 데이터·차액 판단·후보 관리 로직은 변경하지 않았다.

검색에는 실제 label/id와 combobox/list 상태를 연결했다. 지도 레이어와 인근 필지 탐색은 기본 접힘이며 ‘추천부지’ 표현을 ‘필지 탐색’으로 바꿨다. 지도 마커에 의미 있는 접근성 이름을 붙였다. 내비게이션은 실제 링크·현재 페이지·모바일 열기/닫기·Escape 복귀를 제공한다. `/project#sources`, `/project#example` 직접 진입 시 React 렌더 후 해당 제목 포커스와 스크롤을 보장한다.

### 기존 계약 보존

- 보고서는 open 시 snapshot을 고정한다. 지원 지역 A→B 및 지원외 선택으로 바뀌어도 열린 snapshot/print-root는 동일하다. 지원외 새 보고서는 막고 기존 PDF 도구는 유지한다.
- 경로 이탈/초기화는 기존 ReviewApp unmount 및 요청 정리 계약이다. route 왕복 세션 복원과 별개로 print-root는 정리한다.
- AI 기본 off, revision 무효화, TTL clock/포커스/visibility/비교 재평가를 변경하지 않았다. 핵심 엔진·API·constants·session·MemoPanel·report presentation·`index.css` diff는 없다.
- `workspace.css`의 새 검토 스타일은 모두 `@media screen` 안이다. 전역 `.site-shell` 색·본문·nav/footer 및 소개 CSS는 바뀌었지만 `#print-root`는 shell 밖이며 기존 `@media print .site-shell { display:none }`를 유지한다. `.compare-dialog`도 screen 범위다. 최종 A4 전 페이지 재출력은 08에서 수행한다.

- Playwright는 로컬 합성 API/제품 번들을 사용하며 외부 타일 요청을 차단했다. 따라서 지도 캡처의 회색 바탕은 그 검증 조건이다. 실제 OSM 표시 검증과 운영 VWorld/API 성공을 혼동하지 않는다.

### 검증 중 발견·수정한 문제

태블릿 예시 글자 축소, 정면 사진 sizes 불일치, 미포커스 지도 우회 링크 테두리 잔상, `/project#sources` 직접 진입 스크롤 누락, 좁은 입력의 포커스 하단 잘림을 수정했다. 총괄이 추가로 발견한 모바일 메인 제목의 줄바꿈 제거 시 단어 붙음은 명시적 공백으로, 비활성 담기 버튼이 활성 오렌지로 보이던 CSS 우선순위 문제는 disabled 회색 규칙으로 수정했다. 768px 비교는 후보 카드 우선, 1440px는 실제 네 열 폭으로 보완했다. 첫 1320px 비교 모달은 내부 표가 29px 넘치는 검사에서 실패해 1360px/94vw 제한으로 조정 후 재검증했다.

초기 자동화의 rAF 전 관찰 및 부분 label 충돌은 대기·정확한 spinbutton 역할 선택으로 고쳤다. 최초 데이터 명령 `build_all.py --validate-only`는 지원하지 않는 옵션으로 즉시 거절됐으며 데이터 생성/변경은 없었다. 올바른 validator로 다시 통과했다. 이력은 `07-data-initial-command-error.log`, 비교 폭 실패는 `07-flow-failed.json`에 남겼다. 실패 로그와 최종 green 증거를 구분한다.
