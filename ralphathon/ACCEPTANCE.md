## 주요 시나리오의 독립 기대값

- 면적: max(30,000/2, 30,000/4/0.5) = max(15,000, 15,000) = 15,000㎡. 대지 10,000㎡ 부족 5,000㎡, 대지 15,000㎡이면 단순 조건 충족. 10,000㎡ = 3,025평(기존 상수에 맞춘 근삿값); 왕복 오차 조건을 따로 기록한다.
- 금융: 1,000억원 × 0.06 × 12/12 = 60억원. 차입 0은 금융비용 0, 차입 미입력은 계산 보류. 총사업비를 차입으로 대체하지 않는다.
- 비교: 같은 전체 비용 방식의 2,000억원/2,300억원이면 차액 300억원. 어느 후보든 필수항목 누락 또는 방식 다름이면 차액 보류. 하나의 누락을 임의 0으로 메우지 않는다.
- 조회: 정상 미해당, 정상 해당, 부분 실패, HTTP 실패, 잘못된 응답, 응답 지연을 별도 fixture로 둔다. 정상 미해당이 전체 안전을 뜻하지 않는다.
- AI: 제공근거 밖 수치/입지 확정 주장·빈 응답·중단·오류·오래된 의견을 구분한다. 기본 보고서는 계속 가능해야 한다.

## 단계별 실행 인계

1. 문제/레퍼런스/행사 근거 → 총괄 검수 → 별도 설계 반론/구현 계획.
2. 계산/온라인 조회/AI/API 오류·보안 보강 → 별도 회귀 검수.
3. 앱 흐름·보고서/비교·상태 보존 → 별도 실제 브라우저/숫자 검수.
4. 메인/프로젝트/팀·공통 디자인·이미지 → 별도 디자인/접근성 검수.
5. 통합 E2E/폭별/인쇄/응답시간/보안 → 실패 수정 → 필요한 검사 재실행.
6. 새 폴더 재현·PR/배포·실제 연결 및 비로그인 검증.
7. 확인된 서비스 기준 발표5페이지/대본·로그 사본·최종 완료 감사.

각 단계는 전체 목표 일부이며 나머지 요구사항을 폐기하지 않는다. 순서는 의존성과 발견된 위험에 따라 DECISIONS에 이유를 쓰고 조정할 수 있다.
