# 디자인·제품 설계 반론 검수

작성일: 2026-09-21. 검수자: `design_challenge`. **결론: B안은 수정 후 채택 권고. 최종 결정은 총괄이 기록한다.**
범위: AGENTS/GOAL/STATUS/RESEARCH/BASELINE-AUDIT/DESIGN-PROPOSAL과 관련 코드 정적 검토. 이 파일만 작성했으며 코드·브라우저를 변경하거나 실행 품질을 승인하지 않았다.
조사: `tavily-web-research` 적용. Tavily 도구가 없어 web.run으로 세 분석 페이지를 다시 읽었다. preview의 시각 관찰은 RESEARCH의 기존 기록을 인계받았다.

## 2. 엔진 변경은 작은 의미 표시까지만

**완전한 무변경은 권하지 않는다. 새로운 요약 엔진·판정 체계도 필요 없다.** 현재 `ReviewIssue`는 title/detail/tone뿐이고, `engine.ts`의 조례 검토도 risk여서 기존 `summarize()`가 “중대 제약 확인”으로 묶는다. UI 재배치만으로는 오분류가 남는다.
- 기존 `add()` 분기에 안정된 식별자와 표시 분류·근거 성격만 추가한다. 예: 공개자료 해당 사실 / 미확인 / 입력조건 검토. 점수·임계값·면적·비용·적격 여부 산식은 그대로 둔다.
- 공통 요약은 기존 issues에서 만든다. 별도 중복 issues, 범용 증거 그래프, 행동 우선순위 점수, 신규 위험 등급은 보류한다. UI·비교·보고서에 문자열 검색이나 tone 기반 분류를 흩어 넣지 않는다.
- `landUseSource`는 현재 App에서 구분하지만 ScoreInput에 없다는 점을 인계한다. 기존 출처 정보를 공통 연결부와 후보 재계산에 함께 전달하고, 엔진이 알 수 없는 원천을 추정해 “공개자료 확인”으로 붙이지 않는다.
- 상단 종합 문구도 출처·분류를 반영한다. 사용자 선택 조례 검토만 있는 결과에 “중대 제약 확인”을 계속 쓰면 새 소제목만 고친 셈이다. 공개자료 제한 배지와 기존 E 상한은 유지한다.
- 다음 행동은 기존 issues와 actions를 재사용한다. 제약·핵심 미확인·입력 오류에 연결된 순서를 한곳에서 정하고 앞의 3개를 표시한다. `slice(-2)`만 없애려고 행동 관리 모듈을 새로 만들 필요는 없다.
- 변경 전 의도한 분류 기대값을 적고 규제·재해·공급 결측·사용자 용도지역·면적 부족을 검증한다. 대표 산식/점수 골든과 18항목 보고서 회귀는 별도로 유지한다.

## 3. 원천과 유효성의 표시 계약

| 상황 | 화면·비교·보고서가 함께 지킬 표시 |
|---|---|
| 번들 제한 해당 + 실시간 조회 실패 | 확인된 해당 사실과 출처/기준일을 유지하면서 실시간 미확인을 함께 표시한다. 실패 때문에 기존 제한을 없애지 않는다. |
| 재해 구역 해당 / 조회 미해당 | 해당 사실에는 관할기관 확인 행동을 연결한다. 미해당은 조회된 범위의 결과이며 안전 판정으로 확대하지 않는다. |
| 사용자 용도지역 / 공개 조회 용도지역 | 같은 값이어도 원천을 구별한다. 사용자 값이 조회 값을 덮으면 현재 적용값과 조회 근거를 구분하며 공식 확인으로 격상하지 않는다. |
| 입력 면적 부족 / 비용 미입력·0 | 계산 가정과 입력값 기준임을 표시한다. 명시적 0과 결측을 보존하고 결측 비용에는 최저비용·차액을 만들지 않는다. |
| 전력·용수·통신 협의 | 최초 기본 화면에도 미확인을 노출한다. 상태만 confirmed여도 내용·유효 날짜가 없으면 기존 보류를 유지한다. 정상 기록도 “사용자 확인”이며 기관 확약 검증은 아니다. |
| 조회 중·실패·부분 실패 | 기존 source 상태를 보존한다. “제약 0개”보다 “현재 확인된 자료에서 제약 없음 · 미확인 남음”을 쓴다. 근거 키로 상세 출처에 도달하게 한다. |

새로운 일률적 자료 유효기간은 만들지 않는다. 기준일·조회 상태·번들/실시간 원천을 보여주되 오래된 번들을 최신 확인이라고 부르지 않는다. 외부 법적 결론의 재판정은 이번 디자인 변경 범위가 아니다.

## 4. 홈 왕복과 보고서·AI 상태의 결정

**hash 경로와 최초 진입 후 workspace 유지안을 채택하되, 단순 hidden만으로 완료 처리하지 않는다.**
- 최초 home에서는 workspace를 만들지 않는다. 첫 review 이후 상태는 한곳에서 유지한다. 홈·뒤로가기·앞으로가기마다 주소/공통조건/개별조건/4후보가 그대로 돌아오는지 확인한다.
- 홈 이동 시 비교 dialog를 명시적으로 닫고 초점을 홈 제목/시작 버튼으로 옮긴다. 최상위 모달과 body portal은 부모의 hidden만으로 통제되지 않는다.
- `PrintPortal`은 실제로 document.body에 붙는다. 경로가 review이고 유효한 현재 보고서가 있을 때만 인쇄 트리를 활성화한다. 홈에서 Ctrl+P를 눌러 이전 후보 보고서가 나오지 않아야 한다.
- 다시 review를 표시할 때 Leaflet 크기를 재계산한다. “주소로 검토 시작”은 기존 검토가 있으면 “검토 계속하기”로 표시해 재시작 오해를 줄인다. 새로고침 후 복원은 약속하지 않는다.
- **보고서는 별도 모달보다 현재 화면의 명시적 영역을 우선한다.** 상단 “보고서 보기”가 영역을 펼치고 제목으로 이동한다. 비교를 닫고 보고서 모달을 다시 여는 초점·인쇄 복잡도를 줄인다.
- AI 접힘 여부와 보고서 열림 여부는 AI 상태 소유권과 분리한다. 접을 때마다 MemoPanel을 재생성하거나 input/result/checklist를 별도 보고서 state로 복제하지 않는다. ReportPanel 파일 분리는 필수가 아니다.
- 홈으로 나갈 때 진행 중 AI는 중단하고 부분 의견은 완료본처럼 출력하지 않는다. 완료된 유효 의견은 유지할 수 있으나 입력·근거 변경 시 즉시 해제한다. 홈 왕복이나 조건 원상복귀로 invalidated 의견을 복원하지 않는다.
- 기본 PDF는 AI 생성/중지/실패 중에도 가능하다. 최소 구현은 완료되고 현재 서명이 일치하는 AI만 PDF에 포함한다. 부분 생성본 PDF 지원은 보류한다.
- 후보 보고서는 선택 후보를 먼저 복원한 뒤 그 후보의 현재 input/result/rows로 연다. React 상태 반영 전에 바로 print()를 부르지 않는다. 재조회 중이라면 상태를 드러내고 새 응답에 함께 갱신한다.

## 5. 작업 범위와 통과 증거

| 결정 | 이번 구현 범위 |
|---|---|
| 승인 권고 | 경량 메인·직접 review 경로, 오렌지 일관성, 제약/미확인/행동 위계, 상세 선택, 기존 기능 유지, 4후보·개별 보고서·A4 |
| 수정 후 채택 | 엔진 분류 메타데이터 최소 추가, 출처 전달, home 활성 상태와 portal/dialog 통제, 보고서·AI 동선 분리 |
| 보류 | 전면 엔진 재설계, 새로운 UI 프레임워크/라우터, 조건 URL 공유·영구 저장, 네 후보 일괄 PDF, AI 부분본 출력, 대규모 디렉터리 정리 |

390px 비교는 이름 있는 독립 가로 스크롤 표를 허용한다. 고정 항목 열이 후보 열을 가리지 않는지 확인하고, 후보별 지도/보고서/삭제 행동은 헤더 가까이에 둔다. 같은 데이터의 별도 모바일 카드 상태는 만들지 않는다.
상단 세 묶음은 카드 높이보다 실제 문장 길이로 검증한다. 390/768px에서 지도 후 첫 결과·다음 행동·보고서까지 이어지고 문서 전체 가로 넘침이 없어야 한다. 오렌지 대비 제안값은 실제 UI 검증을 대체하지 않는다.

필수 검수 장면:

1. 주소만 선택→상세/AI 없이 보고서·PDF. 미확인 공급조건과 전체 18항목·출처 유지.
2. 제한 해당+조회 실패, 사용자 용도지역, 면적 부족, 비용 null/0을 화면·비교·보고서에서 대조.
3. 4후보→5번째 거절→삭제/추가→공통/개별 변경→선택 후보 보고서의 주소·조건·근거 일치.
4. 열린 비교·보고서·진행/완료 AI 각각에서 home 왕복과 뒤로/앞으로. 숨은 dialog/인쇄 트리·중복 print-root·잃은 초점 없음.
5. AI 완료/생성 중 조건 및 근거 변경→원상복귀. 이전 의견 미복원, 기본 보고서 최신 유지. 기본·상세 A4 모든 페이지 실물 확인.

총괄은 위 수정 조건을 DECISIONS에 확정하고 작은 구현으로 넘길 수 있다. 디자인 선택 승인은 사용성·접근성·회귀·PDF·성능 검증의 통과를 뜻하지 않는다.
